# 组件与本地控制边界

Suite 公开发行版保留七个组件的固定版本源码，并通过一个已鉴权入口使用其功能。组件及固定来源版本见 `components.lock.json`。个人记忆是可自行部署的通用程序；任何使用者的业务数据、录音、历史会话和令牌均不属于公开源码或安装包。

## 千问自动录音

复用 `qwen/engine.py` 的真实 Watcher、音频活动判断、录音触发和 RecordingArchiver。Suite 的独立 Python worker 提供带随机 Bearer 的回环控制接口，不启动旧 tray_app 的无鉴权 8765 服务。浏览状态不启动监听；“启动自动化”和“手动触发”才执行录音相关操作，需要 Windows、已登录的千问客户端以及正确的录音快捷键。

停止按钮停止 Suite 的自动化和归档线程。它不会结束千问客户端内已开始的录音，需在千问中手动停止。已结束录音的备份进入 Suite 本地数据目录，原千问录音保持原位。归档列表在自动化停止时也能查看；归档文件夹名称可能包含个人信息，仅在受保护的本地接口显示。

## 个人记忆

复用原项目的 Node.js `MemoryStore`，通过 Suite 自有的带随机 Bearer 的回环 HTTP worker 提供添加、近期记录、搜索和忘记。Suite 不导入旧 `service.mjs`，因为该入口默认启动历史导入和其他捕获。

新安装的 Codex 历史导入、DSH 历史导入、桌面捕获、Android cloud inbox 四项开关均为关闭。打开某页不会启用它们。用户明确保存开关后才使用原项目对应的导入器或捕获器，并将该选择保存在本机；重启记忆服务恢复已明确设置的开关。历史导入默认只收用户消息。桌面捕获限 Windows；cloud inbox 只读 Suite 本地数据目录里的合规 Android 事件文件，不自动打开网盘同步或云上传服务。

个人记忆不会自动加入 WorkOS 研究模型、DSH 工具或项目事实。搜索结果是本地记录，不能把未确认的历史模型结论当成事实。原存储的“忘记”是软删除：记录不再进入搜索和生成视图，追加日志仍保留旧正文；它不是安全擦除。API 不返回原来源文件路径或工作进程令牌。

## 手机镜像

通过固定的官方 ADB 和 scrcpy 可执行文件提供设备列表、配对码配对、明确地址连接、明确设备镜像和截图。发布包优先使用 `runtime/phone` 中的统一工具；开发环境可回落到固定组件里的工具。Suite 使用独立回环端口的前台 ADB 服务，客户端和 scrcpy 都明确指向它，不替换 5037 上的原服务；退出只停止 Suite 所有的连接进程。状态页不启动 ADB，明确刷新设备或执行手机操作才启动它。mDNS 自动连接关闭，不扫描局域网或断开所有设备，也不接受任意 shell、argv、文件保存路径。[ADB 官方参数实现](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/commandline.cpp)

先在手机的开发者选项打开“无线调试 → 使用配对码配对”，填手机显示的局域网 IP、配对端口和六位代码。配对完成后，用无线调试主页的连接地址执行连接；这两个端口可能不同。设备必须已授权，并在列表中明确选择，Suite 才启动镜像或截图。停止只结束本次 Suite 创建的镜像进程，不终止其他 scrcpy 或 ADB 服务。

旧二维码脚本保留作来源记录，但其自定义 TLS/protobuf 协议不兼容官方 ADB 配对，并存在连接目标错误，因此没有作为可用二维码功能发布。Suite 显示配对码指导，不能把合成测试当成真实设备验证。

## 测试边界

隔离测试会实际启动 Node worker，验证原 MemoryStore 的保存、搜索、软删除、重启持久化和回环 Bearer 鉴权；只使用合成内容和临时目录。手机命令和千问控制不在测试中触碰硬件、麦克风或真实录音。设备授权、千问登录与实际录音效果必须在用户明确操作后检查。
